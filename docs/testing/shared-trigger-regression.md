# 同じトリガー要素を共有するメモの回帰テスト

## 問題

複数のメモが同じDOM要素に一致すると、要素上の単一の登録済みキーが後のメモで上書きされていました。初期ロード後500/1500/3000msの再スキャンやDOM移動の検出が走ると、既存のリスナーが再登録されます。

2つのメモを持つテストでは、1回の操作に対するactivationが期待2回に対してクリック4回、hover/focus8回になりました。クリックは同じ操作の中で表示・非表示を繰り返すため、最終的に非表示になり得ます。

## 修正

登録状態をフック内の `WeakMap<Element, Set<string>>` に置き、要素ごとに全メモのキーを保持します。cleanupでは該当キーだけを外します。ホストページの要素には独自プロパティを書き込みません。

SPA監視、遅延再スキャン、hoverの表示遅延/非表示猶予、クリックの既存トグル条件は維持します。

## 再現と確認

```sh
npm ci --ignore-scripts
npx wxt prepare
npm test -- --run hooks/useActivation.test.ts
npm test -- --run
npm run build
npm run compile
```

`hooks/useActivation.test.ts` は実際のフックをReact Testing Library/jsdomで動かします。時刻とIntersectionObserverはモック、MutationObserverはjsdomの実装です。ストレージは既存テスト設定のモックを使い、実メモや実ブラウザストレージを変更しません。

7ケース:
- 同じセレクタの2メモを再スキャンしても1回ずつ発火し、次のクリックで1回ずつ閉じる
- 異なるセレクタが同じ要素に一致する場合
- hover共有
- focus共有
- 同じDOM要素の移動/再検出
- 新しい一致要素の追加
- メモを1つ除いた再設定とアンマウント後のcleanup

## 記録した結果

ベースcommit `975474a862f5355008584ae24cabd938638feff0` で追加7ケースのうち5ケースが失敗、正常系2ケースが成功。修正後は7ケースすべて成功し、全体76テストとChrome MV3ビルドも成功しました。

`npm run compile` は既存の `chrome` 型定義不足による24エラーで失敗します。修正前のベースcommitを別の作業コピーで型チェックし、同じ24エラーを確認しました。この変更で型チェック全体が成功したとは扱いません。

実Chromeに拡張を読み込むE2E、実サイト、画面上の表示は未検証です。jsdomの回帰テストとビルドの結果です。PRはdraftのままで、タグ作成・リリース・本番配備は行いません。
